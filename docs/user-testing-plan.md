# User Testing Plan

## 1. Testing Objective

Evaluate whether RSU students can easily understand, navigate, and use RSU Nexus to discover, borrow, rent, share, and offer campus resources and services before the final MVP release in Lab 14. The testing will identify usability issues, confusing workflows, and areas for improvement.

---

## 2. Test User Profile

| User Type | Number of Testers | Why This User Type Matters |
|-----------|-------------------|----------------------------|
| RSU Students (Borrowers / Renters / Service Seekers) | 8 | Primary users who search, borrow, rent, or request resources and services. |
| Resource Providers (Students offering equipment, textbooks, tutoring, or services) | 3 | They create listings and manage requests. |
| Admin / Marketplace Manager | 1 | Verifies that listings, requests, and platform management work correctly. |

---

## 3. Testing Tasks

| Task ID | User Task | Related Requirement | Success Criteria | Observation Focus |
|---------|-----------|---------------------|------------------|-------------------|
| T01 | Open the homepage and explain what RSU Nexus is used for. | FR-01 | User correctly understands the platform's purpose within one minute. | Homepage clarity and value proposition. |
| T02 | Search for a DSLR camera, textbook, tutor, or student service using search and filters. | FR-05, FR-06 | User finds the desired listing without assistance. | Search accuracy and filter usability. |
| T03 | Open a listing and review its details before making a request. | FR-07 | User understands the listing information, availability, and owner details. | Detail page clarity and information quality. |
| T04 | Submit a borrowing, rental, or service request through the request form. | FR-03, FR-10, FR-11 | User completes the request successfully without validation errors. | Form usability and validation messages. |
| T05 | Track request status and review the dashboard summary. | FR-08, FR-12 | User understands request status and dashboard information. | Status labels, dashboard readability, and overall usability. |

---

## 4. Testing Procedure

1. Welcome the tester and explain the purpose of the usability test.
2. Briefly introduce RSU Nexus and explain that this is a student prototype.
3. Ask the tester to complete each task independently.
4. Avoid giving hints unless the tester becomes completely stuck.
5. Record task completion, completion time, comments, and any problems encountered.
6. Ask follow-up questions about the overall experience.
7. Thank the tester for participating and record improvement suggestions.

---

## 5. Ethical Reminder

- Participation is voluntary.
- No unnecessary personal or sensitive information will be collected.
- Testing data will be used only for classroom learning and prototype improvement.
- Feedback will remain anonymous in project documentation.
- Testers may stop participating at any time without any consequences.
